# SayaQR audit - 2026-11-07

Reviewed commit: fb84c5f. The findings below describe the original audited state. The subsequent remediation is summarized here; retain the original reproductions as regression references.

## Remediation

All 15 findings have corresponding fixes and regression coverage in the audit-fix change:

- Private service-worker POST sharing, one-time in-memory handoff, sanitized legacy requests, and old-cache removal.
- Required asset caching before readiness/activation, with a worker-confirmed offline status.
- Closed material-part meshes, consistent outward winding, a union surface for STL, and a component assembly for 3MF with no empty objects.
- Sparse support bridges connecting stencil islands; directed-edge, volume, connectivity, and simulated decoding tests replace permissive topology assertions.
- High-precision OBJ coordinates and a preview rendered from the same mesh, with correct dimensions and irrelevant controls hidden.
- Exact structured payload preservation until detail edits, significant Wi-Fi whitespace, address parsing, and explicit notice of supported-field reconstruction.
- Guarded invalid-input rendering, immediate export invalidation, and latest-operation checks for QR/logo imports.
- Literal TXT lines and spreadsheet-formula neutralization in CSV error reports.

Verified after remediation: 177 passing tests; successful production build; local Edge/Playwright smoke tests at desktop, 320 px, and 375 px; private share handoff, offline reload/generation, invalid input, custom colors/logo, and 3D interaction with no page errors. Physical prints and current Bambu/Blender imports still require user testing.

## Findings

### 1. P1 - Share target transmits and persists payloads

Locations: `public/manifest.webmanifest:12`, `public/sw.js:27`, `src/main.ts:1684`.

The installed PWA receives shares by GET, placing title/text/URL into the navigation query. The service worker forwards that full request to the hosting origin and caches it under the query-bearing request key. JavaScript removes the parameters only after navigation. Shared credentials or other sensitive QR content can therefore reach the host and persist in Cache Storage keys, violating the browser-only/no-persistence contract.

Fix: handle shares locally through an intercepted POST and a controlled in-memory handoff, or disable the share target until such a route exists. Never fetch or cache payload-bearing URLs; remove existing sensitive cache entries during migration.

### 2. P1 - Raised exports contain open and overlapping surfaces

Locations: `src/lib/model3d.ts:295`, `src/lib/model3d.ts:308`, `src/lib/model3d.ts:316`.

Reproduction: `validateQr3dMesh(createQrCode("https://example.com", "HIGH"), { reliefMode: "raised" })` returns 866 boundary edges and 3,549 non-manifold edges. The base top omits QR cells without providing the matching closed base boundary; its complete bottom also duplicates the existing underside layer. These surfaces propagate to STL, OBJ, and 3MF.

Fix: construct closed non-overlapping solids for each material, with shared interface coordinates, and validate each exported part and the assembled result.

### 3. P1 - Through-hole stencil has detached islands and diagonal-only contacts

Location: `src/lib/model3d.ts:279`.

The same default URL in engraved mode has 81 non-manifold edges. A four-neighbor flood fill of the remaining solid finds 51 regions, 50 disconnected from the outer frame. Diagonal-only contacts create zero-width connections. Finder centers and other white islands can therefore print as loose pieces instead of one coaster.

Fix: provide a stencil bridge strategy with real printable widths, verify connectivity, and check the resulting scan pattern. A true cut-through QR cannot retain enclosed islands in one piece without some supporting geometry.

### 4. P1 - Surface winding is inconsistent

Locations: `src/lib/model3d.ts:323`, `src/lib/model3d.ts:371`, `src/lib/model3d.ts:288`.

In the default raised example, 1,866 base-top triangles face downward, and QR side walls face inward. Engraved north/south walls also have reversed winding. Edge-count validation does not check orientation. Backface rendering and inside/outside classification can disagree with the intended solid even after edge counts improve.

Fix: enforce outward winding and test opposing directed edges, signed volume, and face orientation on known surfaces.

### 5. P2 - Engraved 3MF builds empty QR and finder objects

Location: `src/lib/model3d.ts:624`.

Engraved geometry returns only material 0, but the package always emits and builds objects for all three materials. QR/finder model objects therefore have zero vertices and zero triangles. These are the empty objects importers may discard or warn about.

Fix: emit only non-empty objects and valid build references. For raised multi-material models, also evaluate a parent component assembly so slicer arrangement cannot separate the aligned parts.

### 6. P1 - Mesh tests explicitly accept broken topology

Locations: `src/test/model3d.test.ts:115`, `src/test/model3d.test.ts:123`.

The raised test requires `boundaryEdges + nonManifoldEdges > 0`. The engraved test accepts `nonManifoldEdges >= 0`, which cannot catch a non-manifold regression. Neither proves the behavior claimed by the test descriptions. Earlier claims that these tests proved watertightness were incorrect.

Fix: require zero defective edges after the geometry is repaired, and add checks for directed winding, per-part closure, connected stencil regions, non-empty 3MF meshes, and exported-coordinate precision.

### 7. P2 - OBJ precision collapses distinct surfaces

Locations: `src/lib/model3d.ts:177`, `src/lib/model3d.ts:480`.

Coordinates are deduplicated in millimeters, then converted to meters and rounded to four decimals. The distinct 0.35 mm and 0.4 mm heights both become 0.0004 m. The default exported OBJ has 5,946 vertex indices but only 5,117 distinct serialized coordinates. This creates coincident unwelded vertices and loses small features, undermining Blender editing/beveling.

Fix: retain sufficient precision in meters and weld using the same coordinates actually serialized.

### 8. P2 - 3D preview differs from engraved output

Locations: `src/main.ts:1157`, `src/main.ts:1166`, `src/main.ts:1172`.

The preview paints a solid base with colored recessed module floors. The export removes the modules as through-holes. Relief changes from 0.4 to 3 mm alter the preview but produce identical engraved STL geometry. The dimension readout adds relief to base thickness even for engraved models.

Fix: render from the same geometry as export, show true openings, disable irrelevant controls in through-hole mode, and calculate actual bounds.

### 9. P2 - Wi-Fi credentials are trimmed

Location: `src/lib/payloads.ts:54`.

All string fields are trimmed, including SSID and password. Valid credentials containing leading/trailing spaces change silently. For example, `S: Network ;P: secret ;` regenerates as `S:Network;P:secret;`.

Fix: preserve exact credential values and apply trimming only to fields whose semantics permit it.

### 10. P2 - Structured imports silently discard source data

Locations: `src/lib/autodetect.ts:83`, `src/lib/autodetect.ts:139`, `src/main.ts:679`.

vCard parsing ignores ADR, so importing a valid contact with an address regenerates a QR without the address. UPI parsing retains only pa/pn/am/cu/tn, dropping fields such as tr, mc, and sign. The source is reconstructed from the partial form without a loss warning.

Fix: preserve the raw payload unless explicitly edited, or retain unsupported fields and warn before a lossy conversion.

### 11. P2 - Invalid input can leave an old QR exportable

Locations: `src/lib/autodetect.ts:63`, `src/main.ts:686`, `src/main.ts:1106`, `src/main.ts:1522`.

`mailto:%` throws URIError from decodeURIComponent before the scheduled QR update. Separately, with 3D preview selected, an oversized payload throws in draw3dPreview before updateQr reaches its guarded encoding block. Old preview/export state can remain visible and enabled while the editor contains different input.

Fix: guard detection and all preview encoding, atomically clear invalid output, and disable exports until generation completes for the current payload.

### 12. P2 - TXT batch input splits payloads at commas

Location: `src/lib/csv.ts:52`.

parseTextList uses the CSV parser and flattens its cells. `Hello, world` becomes two QR rows; `geo:28.6139,77.2090` becomes two invalid fragments. Quotation marks are also interpreted as CSV syntax instead of plain text.

Fix: parse TXT as one literal payload per line; keep CSV parsing separate.

### 13. P2 - Batch report allows spreadsheet formulas

Locations: `src/lib/batch.ts:192`, `src/lib/batch.ts:206`.

The skipped-row CSV includes the original requested filename with CSV quoting only. A requested filename `=1+1` is exported unchanged and can be interpreted as a formula when opened in spreadsheet software.

Fix: neutralize formula prefixes in spreadsheet-facing report fields while keeping the original application data intact.

### 14. P2 - Older imports can overwrite newer choices

Locations: `src/main.ts:1437`, `src/main.ts:2102`.

Image decoding and logo rasterization await work and then apply their results unconditionally. An earlier slow import can overwrite later typing or another import. A pending logo can restore itself after the user selects None or another preset.

Fix: track operation generations and apply only results that still match the latest user action.

### 15. P2 - Offline readiness can be reported with missing app assets

Locations: `public/sw.js:17`, `public/sw.js:54`, `src/main.ts:2217`.

Promise.allSettled ignores JS/CSS caching failures, allowing installation and skipWaiting even if required assets are absent. Registration alone is then used to display Offline ready. A partially cached installation can fail to start offline.

Fix: require successful caching of the essential app shell before activation/readiness, with an explicit failure state and retry path.

## Recommended order

1. Close the share-target privacy gap and stale-output paths.
2. Repair material solids, normals, stencil connectivity, and export precision; replace permissive mesh tests.
3. Align the 3D preview, model bounds, and 3MF object structure with exports.
4. Preserve imported payloads and credentials; fix TXT/report parsing.
5. Add import cancellation and offline installation verification.

The new segmentation tests passed exhaustive small-input bit-cost comparisons, independent QR decoding, all correction levels, version-group boundaries, and fallback cases. No additional segmentation correctness issue was identified in this audit. This is not a proof for every possible input.
